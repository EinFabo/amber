# Baseline profile for Embersay's own code: the classes and methods a start runs, compiled ahead
# of time at install (Play, adb install) or by profileinstaller a moment after the first start
# (an APK installed by hand). The libraries bring their own profiles (Compose, coroutines); this
# file adds ours, which would otherwise run interpreted until the phone's background compile
# picks them up days later.
#
# Hand-written, in the human-readable format AGP merges into assets/dexopt/baseline.prof
# (https://developer.android.com/topic/performance/baselineprofiles/manually-create-measure).
#   L...;            the class is loaded at start (its initialisation goes into the image)
#   H S P            the method is hot / runs at start / runs after start
#   Foo**->**(**)**  every method of Foo and of the classes whose name begins with Foo: its
#                    companion, its nested classes, its lambdas (Foo$..., Foo$$ExternalSynthetic...)
#                    and, for a file, FooKt with its composables
# Rules that match nothing (code R8 removed or inlined) are dropped by the build, not an error.
#
# Covered: the process start (AmethystApp, Graph, the stores it opens), Embersay's screen
# opening on Home and Settings, and the accessibility service connecting with the bubble -
# which is the start most users see: Android restarts the service's process and the bubble has
# to answer the first tap. Not covered on purpose: the introduction (seen once), the dictation
# pipeline and the speech runtimes (they run after a tap, by then warm, and their time is in
# native code), downloads and the secondary screens.
